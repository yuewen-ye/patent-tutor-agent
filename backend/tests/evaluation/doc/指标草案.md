# 指标草案 v1.0

> 目标：整理已实现 / 规划实现的测试指标，明确数据来源和计算公式，并通过文献/行业惯例论证指标的合理性。

---

## 一、总体说明

本文档聚焦三个核心指标大类：**幻觉率**、**用户画像匹配度**、**知识点覆盖率**。每类指标下分若干子维度，按实现状态分为：

| 状态标记 | 含义 |
| :---: | --- |
| ✅ **已实现** | 数据完备，计算逻辑确定，可直接运行脚本出结果 |
| 🔜 **规划实现** | 有明确实现路径（含替代方案），计划在近期迭代中完成 |
| ⚠️ **实现方式待定** | 有概念但路径不确定，或需后续调研后再确定 |
| ❌ **暂不考虑** | 投入产出比低、依赖缺失或比赛未要求 |

所有指标按**单轮**定义；多轮运行取各轮算术平均值作为画像级指标。

---

## 二、幻觉率

> **定义**：课程内容中事实性错误（法条/术语/概念错误）、逻辑瑕疵、虚构引用、误导性推理的比例。

### 2.1 系统自评（专家 Agent 互评 + 裁判 Agent 决策）

| 项目 | 内容 |
|---|---|
| **状态** | ✅ 已实现 |
| **计算方法** | 三个子维度综合得出：<br>① **专家互评异议率** $=\frac{\text{🔴} + \text{🟡}}{\text{总批注数}} \times 100\%$<br>② **裁判准确性评分**：直接取 `judge_report.md` 中 `准确性`（1-5 分制）<br>③ **裁判决策通过率** $=\frac{\text{accept} + \text{accept\_with\_minor\_revision}}{\text{总轮数}} \times 100\%$ |
| **数据来源** | ① `expert_a_cross_review.md` + `expert_b_cross_review.md` 批改意见表格的 `类别` 列<br>② `judge_report.md` → `准确性：X/5`<br>③ `judge_report.md` → `决策：xxx` |
| **字段示例** | 🔴 = 严重事实错误 / 🟡 = 轻微瑕疵 / 🟢 = 正确 / 🔵 = 建议补充 |
| **参考依据** | 多 Agent 互评审（Multi-Agent Debate / Cross-Review）是业界评估 LLM 事实准确性的常用范式，类似学术同行评议。代表工作：Du et al. *"Improving Factuality and Reasoning in Language Models through Multiagent Debate"* (2023)；裁判机制类比 Meta-review / Program Chair，与 ScholarCheck、LLM-as-a-Judge (Zheng et al., 2023) 的评分范式一致。 |

### 2.2 外部 LLM 裁判评分

| 项目 | 内容 |
|---|---|
| **状态** | 🔜 规划实现（下周可以做） |
| **计算方法** | 选取第三方 LLM（与生成端模型不同），将 `course_package.md` 正文拆分为若干原子知识点陈述，每条从三维度独立评分（1-5 分）：事实准确性、来源可靠性、逻辑连贯性。<br>最终：`外部幻觉率 = 任一维度评分 ≤ 3 的陈述数 / 总陈述数 × 100%` |
| **数据来源** | `course_package.md` 全量正文（`knowledge_synthesis`、`legal_basis`、`risks`、`irac` 等结构化字段 + 正文） |
| **参考依据** | 独立评审者与生成端模型不同构（Heterogeneous Judge）可显著降低生成模型对同构评估的过拟合问题（Zheng et al., 2023 *"Judging LLM-as-a-Judge"*），与 TRM-Lab 竞赛端使用独立 Judge 的评估范式一致。 |

### 2.3 语义相似度校验

| 项目 | 内容 |
|---|---|
| **状态** | ❌ 暂不考虑 |
| **原因** | 需引入 Embedding 模型（BGE-M3 已有但需对 course_package 原子事实做拆分 + 重建向量索引），工程实现复杂度高，且当前外部知识库（考试考纲 / 辅导书）尚未完成结构化索引，短期 ROI 低。 |

### 2.4 RAG 溯源标记（替代方案：rerank_score）

| 项目 | 内容 |
|---|---|
| **状态** | 🔜 规划实现（用替代方案） |
| **原方案** | 要求 Expert Agent 输出每个原子事实的 `source_id`，与 RAG 文档分片 ID 绑定。实现难度大：需要改写专家阶段的 tool-calling prompt。 |
| **替代方案（会议讨论结论）** | 系统每个 teach 轮次已生成 `retrieval_context.md`，其中记录了 RAG 检索出的 chunk 及其 `rerank_score`（重排后分数）。<br>**思路**：以 `rerank_score ≥ 阈值` 的 chunk 文本为"可信知识语料库"，用文本覆盖 / 关键词重合来近似衡量 course_package 内容与检索到的权威材料的重合度，未被高置信 chunk 覆盖的陈述 → 计为"疑似非溯源"。<br>`非溯源率 = 不与任一高分 chunk 重叠的陈述数 / 总陈述数 × 100%` |
| **数据来源** | `retrieval_context.md` → 每个 chunk 的 `rerank_score` 字段 + `content` 文本；`course_package.md` 正文。 |
| **参考依据** | 溯源性（Attribution / Groundedness）是 RAG 系统可靠性的核心指标，见 RAGAS 框架的 *Context Precision* 和 *Faithfulness* 指标（Nano et al., 2024）。这里用 RAG 端产出的 rerank_score 作为 chunk 权威度的代理，避免回改专家模型提示词，属于工程可行的 trade-off。 |

### 2.5 模型置信度自评

| 项目 | 内容 |
|---|---|
| **状态** | ❌ 放弃 |
| **原因** | 仅需在 prompt 中要求 Agent 输出 `confidence: 0-1`，实现简单，但置信度校准度差（overconfident / underconfident 普遍存在），与实际幻觉率相关性低，评估意义不大。 |

### 2.6 人工抽检校准

| 项目 | 内容 |
|---|---|
| **状态** | ⚠️ 需要有人来看 |
| **方法** | 每周随机抽取 10-20 条 course_package，依据 SHS（Subjective Hallucination Scale）量表对事实准确性 / 来源可靠性 / 逻辑连贯性 / 误导性 / 响应性做 5 点李克特量表人工评分。<br>人工评分作为 Gold Standard，用于校准自动化指标的阈值。 |
| **参考依据** | 所有 LLM 自动化幻觉率检测都需要人工标注做 Ground Truth 校准。当前行业公认需要 ≥ 300 条人工标注样本才能稳定校准一个分类器阈值。 |

## 三、用户画像匹配度

> **定义**：课程输出的难度、学习风格适配、情感关怀、学习目标覆盖与 LearnerProfile 五维画像的契合程度。

### 3.1 难度符合度

| 项目 | 内容 |
|---|---|
| **状态** | ✅ 已实现 |
| **计算公式** | $难度符合度 = \frac{题目难度 \le 学员能力上限的题数}{总题数} \times 100\%$ |
| **数据来源** | 分子：`course_package.md` → `assessment` 板块每道题的难度标记（形如 `题目1（理解，L1，backward_review）` 中的 `L1/L2/L3`），与 `learning_path.md` 中的难度上限比对，满足 `题目难度 ≤ 难度上限` 即计入分子<br>分母：同上，总题目数<br>难度上限规则（出自 `learning_path.md`）：$P(L)<0.15 \rightarrow L1$；$0.15\le P(L)<0.30 \rightarrow L2$；$P(L)\ge0.30 \rightarrow L3$；薄弱点强制 $\ge L3$ |
| **参考依据** | BKT（Bayesian Knowledge Tracing）的 $P(L)$（Mastery Probability）→ 教学内容难度映射是自适应学习系统（ALEKS、Knewton、iFLYTEK 智慧课堂）的标准工程做法。BKT 模型见 Corbett & Anderson (1994) *"Knowledge Tracing: Modeling the Acquisition of Procedural Knowledge"*。难度匹配原则为"最近发展区"（Vygotsky, 1978）——难度既不显著高于能力（引起挫败）也不显著低于能力（无聊），$难度 \le 上限$ 是宽松约束。 |

### 3.2 风格匹配度（领域符合度 + 认知层级 合并）

| 项目 | 内容 |
|---|---|
| **状态** | 🔜 规划实现（合并后的口径） |
| **合并说明** | 原来的"领域符合度"和"认知层级匹配"在实操中数据来源和判断逻辑高度耦合：**都是 course_package 中的教学模块/题目类型** vs **learner_profile 中的风格/目标维度**的匹配。现合并为"风格匹配度"一个统一指标。 |
| **计算公式** | $风格匹配度 = \frac{匹配学员风格的自适应板块数}{自适应板块总数} \times 100\%$<br>其中"匹配"定义为：`教学模块选择清单` 表格中，`类型 = 自适应` 的板块，其 `触发原因 (trigger)` 字段显式引用了学员画像中的下列维度之一：<br>① Felder-Silverman 风格维度（sensing/intuitive, visual/verbal, active/reflective, sequential/global）——即"认知层级"维度<br>② 学习目标（learning_goal）覆盖的领域标签——即"领域符合度"维度 |
| **数据来源** | 分子：`course_package.md` → `教学模块选择清单` 表格 → 逐行读取 `触发原因 (trigger)` 列，检查该文本是否与 `learner_profile.md` 中 style/cognition/progress 的对应维度标签重合，重合则计入<br>分母：同上表格中 `类型 = 自适应` 的行数总和 |
| **参考依据** | Felder-Silverman 学习风格模型（Felder & Silverman, 1988）与教学内容匹配的工程化实现参考了 Aha!、可汗学院的自适应教学模块选择逻辑，"trigger → style/cognition dimension" 映射在智能辅导系统文献中被称为 *Content-Style Alignment Score*。学习目标覆盖属于经典的 *Curriculum-Objective Alignment* 问题（Marzano, 2001）。 |

### 3.3 情感状态适配度

| 项目 | 内容 |
|---|---|
| **状态** | ✅ 已实现（简单测量） |
| **计算公式** | $情感适配度 = \frac{情感支持板块数}{总教学板块数} \times 100\%$ |
| **数据来源** | 分子：`course_package.md` → `教学模块选择清单` 表格 → `模块 (block_type)` 列属于以下情感支持类型的板块数量：`anchor_scenario`（场景导入）、`worked_example`（案例演示）、`decision_flow`（决策引导）、`mnemonic`（记忆术）、`summary_card`（速查卡）、`analogy`（类比）<br>分母：同上表格总板块数<br>学员情感状态参考：`learner_profile.md` → `affect`（如 `confused`、置信度）——作为判定"是否需要更高的适配度"的依据（如学员 confused 时情感模块占比应更高） |
| **参考依据** | 情感计算（Affective Computing，Picard, 1997）在教育场景中的应用：D’Mello et al. (2007) 表明当学习者处于 Confusion/Frustration 状态时，教学系统应增加 Scenario/Walkthrough/Scaffolding 类情感支撑模块比例。简单的 block_type 分类是业界 ITS 系统情感适配检测的工程化 baseline。 |

## 四、知识点覆盖率

> **定义**：课程内容实际覆盖了多少预设应覆盖的知识点、薄弱点、混淆对。预设答案基于该轮的实际路径规划结果人工编写。比赛答疑中仅要求"本节覆盖率"，"多轮覆盖率"未提及，因未做多轮迭代故不纳入本版方案。

### 4.1 本节知识点覆盖率

| 项目 | 内容 |
|---|---|
| **状态** | ✅ 已实现（测量方式可能调整） |
| **计算公式** | $本节覆盖率 = \frac{\|Covered \cap Expected\|}{\|Expected\|} \times 100\%$<br>即课程实际覆盖的知识点集合与预设答案期望覆盖的知识点集合之交集大小 / 期望大小 |
| **当前测量方式** | 分子：`course_package.md` 结构化数据段 → `"knowledge_points[].node_id"` 数组（已覆盖的节点 ID）<br>分母：`expected_{学员首字母}_{NN}.json` → `expected_course_content.section_kcs[]`（预设本节应覆盖的章节级 node_id） |
| **可能调整（测量方式待确认）** | 当前 `knowledge_points[]` 实际填充较空（LLM 未输出），可改为从 `course_package.md` 正文中用关键词匹配（匹配 `knowledge-dag.json` 中所有节点的 node_name 中文名）重新计算 $Covered$ 集合，避免依赖结构化段。 |
| **预设答案编写时机** | 系统运行结束后，测试人员依据该轮的 `learning_path.md` / `path_decision.md` 的当前节点规划结果，结合画像薄弱点，查 `knowledge-dag.json` 手动编写。 |
| **参考依据** | 内容-目标对齐度（Content-Objective Alignment）是教育评估的经典指标（Rothman, 1998 *"Curriculum Alignment Research"*），在国内智慧教育国标（GB/T 36351 等）中被称为"知识点覆盖率"，定义一致：$Coverage = \frac{\|C \cap O\|}{\|O\|}$，其中 $C$ 是实际内容，$O$ 是目标内容。 |

### 4.2 多轮覆盖率

| 项目 | 内容 |
|---|---|
| **状态** | ❌ 暂不考虑（比赛答疑未提及 + 未做多轮迭代） |
| **原因** | 本轮方案的 scope 中，比赛答疑仅要求"本节覆盖率"。多轮覆盖率需要完整推进 67 节点全量学习，耗时与 LLM Token 成本极高，不在本次验收范围内。 |

### 4.3 薄弱点命中率

| 项目 | 内容 |
|---|---|
| **状态** | ✅ 已实现 |
| **计算公式** | $薄弱点命中率 = \frac{\|Hits \cap Weak\|}{\|Weak\|} \times 100\%$ |
| **数据来源** | 分子：从 `course_package.md` 的 `knowledge_synthesis.framework` / `must_know` / `risks[].risk` 正文文本中，搜索匹配预设答案中的薄弱知识点名称（中文），命中数计入<br>分母：`expected_{学员首字母}_{NN}.json` → `expected_course_content.weakness_kcs[]`（预设薄弱知识点的中文 node_name） |
| **参考依据** | 薄弱点（Prerequisite Deficit / Misconception）的针对性补救是 BKT 与认知诊断（CDF, DINA 模型）自适应教学系统的核心产出指标。De la Torre & Minchen (2014) 将薄弱点覆盖率定义为 $Remediation\ Ratio = \frac{N_{fixed}}{N_{weak}}$，与上述公式等价。 |

### 4.4 混淆风险覆盖率（混淆对覆盖率）

| 项目 | 内容 |
|---|---|
| **状态** | ✅ 已实现 |
| **计算公式** | $混淆风险覆盖率 = \frac{\|Pairs_{course} \cap Pairs_{exp}\|}{\|Pairs_{exp}\|} \times 100\%$ |
| **数据来源** | 分子：从 `course_package.md` 的 `knowledge_synthesis.key_relations` / `risks[].risk` 正文中，匹配预设答案中的混淆对（node_id 对，不区分顺序，即 `[a,b]` 与 `[b,a]` 视为同一对），命中数计入<br>分母：`expected_{学员首字母}_{NN}.json` → `expected_course_content.confusable_pairs[]`（预设混淆对列表） |
| **参考依据** | 认知科学中，概念混淆（Conceptual Confusion）会显著降低学习迁移率（Thagard, 2006）。智能辅导系统中通常将混淆对作为"对比辨析"专项教学单元。混淆对覆盖率 = "系统辨析的高风险混淆 / 应辨析总数" 的比例，在认知诊断评估框架中称为 *Misconception Remediation Coverage*。 |

## 六、指标取舍的论证小结

1. **取舍原则**：优先满足比赛答疑明确要求的指标（覆盖率的"本节覆盖" + "混淆对" + "薄弱点" + 幻觉率系统自评 + 难度符合度），在人力和工程成本允许的前提下扩展"高性价比"指标（外部 LLM 裁判、rerank_score 溯源、风格匹配度）。

2. **舍弃项理由**：
   - 语义相似度：需 Embedding+重建知识库索引，工程成本高且比赛未强制要求 → 舍弃
   - 多轮覆盖率：未做多轮全路径迭代，且比赛未提及 → 舍弃
   - 模型置信度自评：与实际幻觉率相关性低，业界公认意义不大 → 舍弃

3. **替代方案合理性**：
   - RAG 溯源标记用 `rerank_score`（chunk 权威度）替代原子事实 `source_id` 绑定，避免改写专家阶段 prompt，是工程可行的 trade-off，思路上沿用了 RAGAS Faithfulness 的"groundedness with top-ranked evidence"定义。
   - 风格匹配度将"领域符合度 + 认知层级"合并，因为两者在数据层面共享同一载体（`教学模块选择清单` 的 trigger 字段），分离计算只会增加代码复杂度而不提升指标区分度。
