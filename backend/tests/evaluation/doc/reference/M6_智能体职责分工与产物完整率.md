## 一、职责分工说明（6 个独立分工智能体）

系统采用多 Agent 专利辅导工作流，核心教学链路由 **6 个职责清晰的智能体节点** 组成（另有 `chat_answer` 仅服务于闲聊意图，不计入核心辅导链路）：

| 智能体节点 | LLM 提供方 / 模型 | 职责分工 | 产出 |
|---|---|---|---|
| `route` | terra / gpt-5.6-terra | 意图分类：teach / chat / diagnose | `intent` |
| `diagnosis_feedback` | terra / gpt-5.6-terra | 诊断学情 或 答疑反馈（按阶段选择） | `learner_profile`、`feedback_result` |
| `planner` | terra / gpt-5.6-terra | 读取画像与 BKT，计算双轴学习路径 | `dual_axis_snapshot`、`learning_path`、`path_decision` |
| `expert_a` | terra / gpt-5.6-terra | 起草课程、审 expert_b、修订、整合 | A 侧 draft/cross_review/revision、`course_package` |
| `expert_b` | deepseek / deepseek-v4-flash | 起草课程、审 expert_a、修订 | B 侧 draft/cross_review/revision |
| `judge` | grok / grok-4.5 | 评估整合后课程（不改写） | `judge_report` |

> 注：`expert_a` 与 `expert_b` 构成「辩论 + 交叉验证」双专家机制（AGENTS.md 明示 `expert_review` = 专家互审，非独立节点）；`judge` 为独立裁决方。这满足赛题「≥3 个智能体分工」「分析-生成-校验-决策闭环」双重要求。

## 二、闭环链路（分析-生成-校验-决策）

```
route(分类)
  └─ diagnose → diagnosis_feedback(诊断) → END
  └─ teach    → diagnosis_feedback(诊断)
             → planner(路径规划)
             → expert_a[draft] ⇄ expert_b[draft]      （双专家起草）
             → expert_a[cross_review] ⇄ expert_b[cross_review]  （交叉验证/辩论）
             → expert_a[revision] ⇄ expert_b[revision]        （修订）
             → expert_a[integration] → judge(裁决)
                  └─ 不通过 → 回到 integration 循环，直至通过
```

## 三、各轮产物完整率

- **定义**：五类产物（规划 / 专家A / 专家B / 裁判 / 诊断反馈）齐全且非空的轮次 ÷ 总轮次 × 100%
- **各轮判定文件**：
